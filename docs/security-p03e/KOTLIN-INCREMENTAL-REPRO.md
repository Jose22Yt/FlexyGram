# Protocolo futuro: incidencia incremental Kotlin

Referencia: [fallo incremental original](../security-p03d/evidence/gradle-incremental-failure.log), [ejecución final exitosa](../security-p03d/evidence/gradle-final.log), [herramientas exactas](../security-p03d/evidence/tool-versions.json), [resultado](../security-p03d/evidence/build-result.json).

Hecho: compileDebugKotlin falló en 35 s al recompilar Translator.kt, indicando declaraciones conflictivas de code2Locale, locale2code y LocaleInfo.locale, y ambigüedades derivadas. La búsqueda encontró una sola definición fuente de esas extensiones. La repetición con `-Pkotlin.incremental=false`, sin parchear esas funciones ni cambiar dependencias/gradle.properties, terminó en BUILD SUCCESSFUL/exit0 (1m41s). La APK final incluía las dos guardas adicionales y fue verificada estáticamente.

Contexto relevante: durante la primera ejecución exitosa de P0.3d se añadieron las dos guardas de contexto/encuesta **después de que Kotlin hubiera compilado y mientras continuaba la construcción nativa**. La ejecución siguiente era incremental. Hubo sesiones múltiples de daemon. Una modificación del workspace durante un build puede afectar las suposiciones de sus snapshots; ni esto ni una versión concreta de AGP/Kotlin se han demostrado como causa. No se conserva un snapshot completo e independiente de cada instante intermedio: no se promete reproducir exactamente el historial.

No se ejecuta este protocolo ahora. Antes de una prueba futura autorizada:

1. Checkout/worktree limpio del commit aprobado `97b5972c03ced57e17b54ff6af5a8ea516785a7c`, con todos los submódulos fijados. Conservar main/develop y la rama de seguridad sin cambios. Copiar hashes de fuente/clases e inventario, fuente congelada durante cada build; sin cuentas ni ejecución de app.
2. Usar las versiones de tool-versions.json (JDK JetBrains21, Gradle9.7.1, AGP9.3.1, SDK37/35, BT36, NDK27.2.12479018, CMake3.31.6, Python3.11/Chaquopy17). GRADLE_USER_HOME nuevo para el caso limpio y copia separada para cada control; registrar SO, memoria, Java, hashes y flags. CMAKE explícito al SDK. Firma de laboratorio privada fuera de Git; no imprimir variables/contraseñas.
3. Control A: `:TMessagesProj:assembleDebug --no-daemon --max-workers=2 --no-build-cache -Pkotlin.incremental=true`, esperando a su finalización y registrando salida completa/exit. Repetir sin modificar fuentes y luego con un cambio documental/comentario Kotlin local reversible, fuera de commits. Es un control de edición entre builds, no reproducción garantizada del fallo histórico.
4. Control B: mismo estado fuente y herramientas, workspace/caché independiente, `-Pkotlin.incremental=false`. Comparar diagnósticos, classpaths, archivos TranslatorKt/metadata Kotlin y compilación de módulos. Conservar cada snapshot antes/después, no borrar evidencia para conseguir éxito. Un fallo de red/descarga o falta de CMake no cuenta como reproducción de ambigüedad Kotlin.
5. Solo si el caso limpio no reproduce: diseñar y aprobar una prueba controlada del cambio de fuentes mientras el build está en curso, con logs/timestamps y revisiones recuperables. No relajar guardas de seguridad ni introducir condiciones de carrera en ramas de desarrollo para intentar provocarlo.

No persistir opciones nuevas en gradle.properties/build.gradle, no actualizar versiones ni cambiar código de navegación/rendimiento. El workaround CLI documentado no es una optimización ni una solución universal. No instalar, distribuir ni autenticar ninguna APK de reproducción. P0.3e conserva el código/configuración de producción intactos.
