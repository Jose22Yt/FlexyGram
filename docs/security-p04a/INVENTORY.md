# Inventario estático a partir de P0.3g

Base examinada: `781b18be703809898ac0478c6239d53216ebd736`; código aprobado en `86226a55d59c2bac5a85516a1ab4d97a67801961`. No se publican valores de credenciales heredadas.

|---|---|---|
| `gradle.properties`, `TMessagesProj/build.gradle` | APP_PACKAGE `io.github.jose22yt.flexygram.diagnostic`; comprobación que rechaza otro ID | Declaración por flavor con IDs distintos, no sustitución global |
| `settings.gradle`, nombre de APK en build.gradle | rootProject `exteraless`, nombre de archivo comienza exteraless | Nombres de proyecto/artefacto FlexyGram por variante, sin cambiar paquetes Java/JNI |

| `res/values/strings.xml` y recursos localizados | AppName=exteraless, AppNameBeta=Telegram Beta en recursos base; etiqueta principal no los usa | Sobrescrituras coherentes y auditoría de referencias/traducciones antes de cambiar; evitar marca engañosa |
| `res/xml/auth.xml`, `sync_contacts.xml` | accountType diagnóstico; iconos heredados; contentAuthority de sincronización `com.android.contacts` | accountType propio por flavor; mantener autoridad Android legítima si se aprueba contactos, no sustituir com.android.contacts por un ID inventado |

| Manifiesto, enlaces y servicios | Esquemas heredados como tgb, ton y wear/tg-wear-auth; integraciones Wear/Auto/multimedia restringidas por diagnóstico | No reactivar por cambiar flavor: permisos/exportados/intents requieren autorización individual y pruebas de entrada externa |
| `namespace`, paquetes `org.telegram.*`, `tw.nekomimi.*`, `app.exteraless.*`, JNI | Namespace `org.telegram.messenger` es distinto del applicationId | No renombrado masivo: rompería JNI, reflexión y contratos. | `gradle/telegram-api.gradle`, BuildConfig | Resolver admite par privado completo de una sola fuente y rechaza valores incompletos; resultado actual no habilita credenciales: APP_ID=0, APP_HASH vacío | Validación de forma no demuestra propiedad. | `DiagnosticPolicy.java`, puntos de uso en ApplicationLoader, LaunchActivity, ConnectionsManager, plugins, sockets y servicios | BuildConfig.ISOLATED_DIAGNOSTIC=true incondicional en todos los buildTypes | Inventario de callsites y pruebas positivas/negativas antes de separar capacidades; no convertir la preferencia del usuario en bypass |

| TranslationServicesPolicy, GoogleTranslator.kt, fallback/GoogleTranslatorNeko.java | Política deniega incluso fuera de Diagnostic; adaptadores Google deniegan localmente | Políticas/adaptadores explícitos por variante; cambiar solo ISOLATED_DIAGNOSTIC no habilita traducción |
| `settings.gradle`, `:translation-compat-diagnostic`, verificadores Gradle | Módulo fuente de seis clases, denegación permanente, dependencia exclusivamente diagnóstica; AAR heredado excluido | Módulos mutuamente exclusivos por variante, contratos Translator/HTMLKeeper/TLRPC estables; producción no puede depender de esta fachada ni volver al AAR antiguo |
| PushServicesPolicy, `gradle/push-services.gradle`, callbacks FCM/UnifiedPush | Configurador recibe diagnóstico=true; scope/package/project verificados; inicialización/tokens denegados; crash reporting no autorizado | Futura configuración propia opcional. | Dependencias Firebase/GMS, plugins raíz | SDKs siguen en el grafo; plugins Google Services/Crashlytics declarados apply false | Presencia de SDK no equivale a servicio autorizado. Auditar inicializadores fusionados de producción y aplicar plugins/config solo si corresponde, sin recursos/gateway de terceros |
| Firma en build.gradle | Debug usa keystore diagnóstico fuera de Git; staging y release asignan signingConfigs.debug; existe declaración release no elegida | Release actual NO tiene firma de producción. Prohibir fallback diagnóstico en futura producción |
| BackupAgent, SettingsBackupPolicy y reglas XML | Sesiones no restaurables; ajustes exportables por allowlist; descarte de archivos corregido en P0.3a | Mantener protección común a ambas variantes; futuros ajustes de política no pueden reabrir credenciales |
| Código nativo/Python, licencias | Submódulos y binarios heredados, licencia raíz GPLv3 y avisos de dependencias | Inventario de procedencia, versiones y obligaciones por componente; preservar Telegram, Exteraless, Nekogram, NekoX y demás autores según sus archivos reales, no atribuir su código exclusivamente a FlexyGram |

Los históricos `docs/translation-safety-preparation` y P0.3c describen etapas anteriores: no indican que las dos claves Google continúen en el grafo activo de P0.3g. El escaneo aprobado dio cero coincidencias de las claves/identidades investigadas; no es una garantía universal de ausencia de cualquier secreto en todo el proyecto. No reincorporar el AAR retirado para recuperar Microsoft/DeepL.

Inventario de datos a completar en implementación: todas las rutas calculadas por ApplicationLoader/FileLoader/SharedConfig/UserConfig/MessagesStorage, almacenamiento externo heredado, preferencias de cuentas, AccountManager, ContentProvider y URIs, enlaces, shortcuts, grupos/canales de notificaciones, nombres de copias/exportaciones y caches de tokens por scope. La separación por ID no autoriza importar carpetas Exteraless ni capturar sus enlaces/cuentas. Las rutas que no dependan del sandbox deben tener pruebas explícitas antes de beta.
