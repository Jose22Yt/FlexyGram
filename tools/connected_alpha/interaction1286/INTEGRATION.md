# Alpha 1286 — Signature Interaction / Liquid Navigation / Bubble Fusion / Share Sheet

Base: PR129 `e0c8e1b78acc120481cc9675de149771f59ddd6c`. No newer validated integration existed when this task started. PR130 is a draft continuation, not a merge or Beta/identity migration.

## Implemented paths

1. **Single-contact bubble response.** `ChatMessageCell.onTouchEvent` first runs every native control hit test. Only an unclaimed message background starts `BubbleTapMotion`; it does not consume the native gesture. The chat list observes UP/MOVE/CANCEL/pointer changes. The cell and its parent-drawn background use the same canvas scale. Long press, recycling and detach clear ownership. The frame-clock spring does not use a global motion engine or platform duration scaling. Screen reader/reduced-motion policy avoids the animation. Separate persistent controls: animation, compression, rebound, recovery speed, single-tap native reactions/panel, reset. The panel option defaults OFF; animation defaults ON. When enabled, panel-on-tap takes priority over configured double-tap recognition for unclaimed bubble backgrounds. Native links/media/spoilers/buttons retain their own actions.
2. **Horizontal lens.** Rest geometry uses one uniform bar-wide slot constraint and never interpolates a destination's text width. The renderer uses a rounded horizontal capsule path, bounded to aspect ratio >=1.55. Only the lens expands on contact and follows drag; outer view properties stay 1. Native backdrop/reflections are retained. The capsule has a reserved 16dp drawing margin on each vertical side so expansion can overhang its surface while staying inside this local view. Gesture cancellation releases springs and pending callbacks.
3. **All nine real destinations.** Sanitization no longer discards destination 7–9. Scrollable is the default distribution; More is an explicit alternative. Slots retain >=48dp touch widths. Drag outside the selected lens scrolls the tab strip; drag originating on the lens moves it and supports bounded edge auto-scroll. Reorder uses stable destination IDs and the existing native routes. Selection can reveal an offscreen destination; logical RTL priority remains intact. Normal/Compact/Very compact/Automatic/Custom profiles and safe geometry controls persist. Alpha1285 height migrates once into Custom without resetting order.
4. **Settings and preview.** Compact root opens focused movement, lens appearance, dimensions and presets pages, plus the native reorder editor. Preview includes a fictitious FlexyGram header, folders and conversations with the actual production bar/renderer/gestures. It never reads real names, photos or messages; profile uses a synthetic icon, not the account avatar. Slider changes update views without reconstructing the fragment. Label/icon spacing and system-edge clearances are bounded. Native power policy still gates optical effects; adaptive quality reduces optics under peak deformation.
5. **Bubble Fusion 2.0.** None / Classic / Enhanced are independent from original outline styles. The old fusion flag migrates to Classic. Enhanced uses cached palette colors and two low-alpha in-silhouette bands before the existing contour. Strength and theme adaptation are real persistent settings; zero strength matches None. Native blur, fill/gradient/transparency, contour position and path/tail stay authoritative. No new per-frame path/shader allocations, Bubble Glass or Matte.
6. **Flexy Share Sheet.** Opt-in under Appearance, with compact local content summary, selected-recipient names/count and explicit Classic fallback in the existing native `ShareAlert`. Native search, recipients/topics, paid-send restrictions and `sendInternal` remain byte-identical. Account resolves from the source fragment/message before creating adapters. Ordinary allowed text/photo/video/document forwarding can enter this native sheet. Secret chats, polls, tasks, invoices and monoforum special forwarding retain the original picker. No replacement send pipeline or external rendering service. Preview is bounded text/caption/type/filename; there is no new media-thumbnail decoder or filesystem export. Call/fullscreen share flows keep native presentation. Classic switch changes presentation without discarding selection/search. Design inspiration: contest.com/design-2026/entry7553, Humble Cockroach. The public ZIP/channel could not be retrieved completely in this environment; no pixel-equivalence or ready-made Android code claim is made.

## Validation and evidence boundaries

- Phase checkpoints: 15 context/tap tests, 21 production navigation tests including migration and 2–9 slots, 8 preview/settings/share-header tests, 42 production bubble/blur/preview tests, 8 current integration checks. Later exact-source CI is authoritative for the delivered commit.
- Source/host parity runs through the original `run_checks.py`; all historical manifests stay immutable. The new exact delta layer rejects unknown bytes and projects approved changes only for historical audits. The old assertion that Alpha1285 had no tap controller now checks that exact historical source; current route/lifecycle/graphics checks cover its explicitly authorized replacement.
- API37 resource linking and the full native ARM64 build are separate gates. Only a successful final workflow plus signature/package/hash/download verification qualifies an APK for private delivery.
- PNGs named `*isolated*` are Android graphics probes using production drawables/motion/bar/preview with explicit account, fragment, GPU backdrop and tab-content doubles. They contain synthetic data and do **not** prove whole-app rendering, end-to-end touch arbitration or physical Poco performance.
- Physical acceptance remains required: single tap vs long press, interactive controls, selection/cancel/repeated taps; expanded lens/edge auto-scroll, all 2–9 configurations and overflow, RTL/landscape/font sizes; fusion themes/wallpapers; text/media forwarding to multiple allowed destinations and restrictions. Real server sends, login and 60/120/144Hz frame traces are NOT_TESTED here.

## Rollback and installation

Package and signing identity stay the existing installed Alpha identity. A verified higher versionCode APK is an update; do not uninstall or clear account data. No Beta or public release promotion. If runtime regression occurs, disable the new opt-in panel/share features and select Classic presentation/None fusion; preserve logs for diagnosis. Git rollback is to PR129 source above and requires an appropriately incremented signed versionCode for installation over this APK; Android will reject a lower versionCode through normal update installation.
