## Main-tab drag checkpoint

MainTabsLayout now uses the same coordinator for the two existing drag/settle pixel properties and its existing 1.019 root long-press pulse. Native click/selection order, direct finger writes, pivot mapping, geometry, hit bounds and long-press timing remain unchanged. The two unused scale spring instances/commented calls are removed. A lazy bounded-property adapter synchronizes external finger writes before retargeting and on profile changes; pixel-specific settling (.5px/30px per second) avoids retaining normalized-value micro-thresholds for invisible tails. No per-frame allocation or second clock is introduced.

Flash/reduced motion skip the root pulse and selector restoration delay, and settle immediately. Flow/Signature use local settings. Detach or window hide cancels ClickHelper's pending long press without committing navigation, removes the selector restore callback and disposes all three drivers; reattachment creates them on demand. ClickHelper itself is unchanged. Its existing cancel method invokes finish for an active long press, so the host suppresses that selection callback during lifecycle cleanup. Native isolated tests extract exact production gesture/driver methods with real Android View and ClickHelper; only theme, horizontal fixture layout and child GlassTabView selection rendering are explicit doubles. This is not a full MainTabsLayout/AnimatedLinearLayout integration test. Child tab selection, inherited item layout transitions and active Work1 FilterTabsView remain native; do not describe the whole navigation system as migrated.
